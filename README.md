# Наши траты — Telegram Mini App для двоих

Учёт личных и совместных трат для двух пользователей (вы и ваша девушка).
Только личное использование, всё на бесплатных тарифах.

## Принятые решения (зафиксированные ответы + дефолты)

| Вопрос | Решение |
|---|---|
| Общий котёл / раздельно | **Раздельно, видно обоих**: каждая трата принадлежит автору, видны обе ленты, итоги по каждому и общая сумма. Никаких «кто кому должен». |
| Категории | **Фиксированные 7**: Еда, Транспорт, Жильё, Развлечения, Здоровье, Подарки, Прочее. «Пометки» — поле комментария у каждой траты (до 500 символов). |
| Бюджет | **Один общий на месяц**, хранится в таблице `budgets`, задаётся/меняется прямо в приложении. Индикатор «осталось / превышено». |
| Редактирование | По умолчанию **каждый редактирует и удаляет только свои записи**. Бюджет могут менять оба. |

## Архитектура и почему так

```
Telegram клиент (Mini App)
   │  каждый запрос: { action, initData, payload }
   ▼
Supabase Edge Function `api`  ← секрет TELEGRAM_BOT_TOKEN только здесь
   │  1. HMAC-валидация initData (алгоритм Telegram)
   │  2. проверка allowed_users (белый список из 2 ID)
   │  3. права: изменять можно только свои записи
   ▼
Postgres (service_role)  ← RLS включён, политик для anon нет = прямой доступ запрещён
```

**Proxy-режим вместо кастомного JWT.** Функция валидирует подпись initData при
каждом запросе и сама ходит в БД. Плюсы: не нужен JWT-секрет и логика
выпуска/протухания токенов; вся проверка прав в одном месте; frontend вообще
не знает ключей Supabase. Минус: каждый запрос проходит через функцию —
для двоих пользователей это несущественно (лимит 500 000 вызовов/мес).

**allowed_users — таблица, а не переменная функции.** Добавить/убрать
пользователя можно одним SQL-запросом в SQL Editor, без редеплоя функции.

**service_role обходит RLS**, поэтому правило «только свои записи» проверяется
в коде функции (см. `case "update"` / `"delete"`). RLS при этом включён на всех
таблицах без политик — это гарантирует, что напрямую через anon key никто
(даже зная URL проекта) ничего не прочитает и не запишет.

## Структура проекта

```
tg-expenses/
├── frontend/                 → деплоится на GitHub Pages / Vercel
│   ├── index.html
│   ├── app.js
│   ├── styles.css
│   └── config.js             ← сюда вставить URL функции (публичный, не секрет)
├── supabase/
│   ├── migrations/0001_init.sql   ← выполнить в SQL Editor
│   ├── functions/api/index.ts     ← код Edge Function
│   └── config.toml                ← для CLI-деплоя (verify_jwt = false)
└── .github/workflows/
    ├── deploy-pages.yml      ← автодеплой frontend на GitHub Pages
    └── keepalive.yml         ← пинг Supabase раз в 3 дня (не даёт уснуть)
```

# Развёртывание с нуля

## Шаг 1 — создайте бота

1. В Telegram откройте **@BotFather** → `/newbot` → имя и username бота.
2. Сохраните **токен бота** (вида `123456789:AAF...`). Это секрет — он пойдёт
   только в Supabase secrets, никогда во frontend и не в git.
3. Узнайте **Telegram ID** обоих пользователей: напишите боту **@userinfobot**
   (или @getmyid_bot) — он вернёт числовой ID. Понадобятся два числа.

## Шаг 2 — создайте проект Supabase

1. Зайдите на [supabase.com](https://supabase.com) → Sign in (через GitHub) →
   **New project**. Регион — ближайший (например, Frankfurt). Free plan.
   Дождитесь создания (~2 мин).
2. **SQL Editor → New query** → вставьте целиком содержимое
   `supabase/migrations/0001_init.sql`.
   **Перед запуском замените** `111111111` и `222222222` на реальные ID из шага 1.
   Нажмите **Run**.
3. Создайте функцию: **Edge Functions → Create a new function** (via Dashboard):
   - имя: `api`;
   - **выключите тумблер «Verify JWT»** (функция валидирует initData сама);
   - в редактор вставьте код из `supabase/functions/api/index.ts` → **Deploy**.
4. Задайте секрет: **Edge Functions → api → Secrets** (или
   Project Settings → Edge Functions → Add new secret):
   - Name: `TELEGRAM_BOT_TOKEN`, Value: токен из шага 1.
   - `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет
     автоматически — их задавать НЕ нужно.

> Альтернатива через CLI (необязательно):
> ```bash
> npm i -g supabase
> supabase login
> supabase link --project-ref YOUR_PROJECT_REF
> supabase db push          # применит миграции (или выполните SQL вручную, как выше)
> supabase secrets set TELEGRAM_BOT_TOKEN=123456789:AAF...
> supabase functions deploy api --no-verify-jwt
> ```

## Шаг 3 — пропишите ключи во frontend

Единственное, что нужно вставить, — **публичный URL функции**.

Где взять: **Project Settings → General → Reference ID** (или Project URL).

Откройте `frontend/config.js` и замените `YOUR_PROJECT_REF`:

```js
window.APP_CONFIG = {
  API_URL: "https://abcdefgh12345.supabase.co/functions/v1/api",
};
```

Больше никаких ключей во frontend нет: anon key не нужен (proxy-режим),
токен бота и service_role живут только в Supabase.

## Шаг 4 — задеплойте frontend

Нужен HTTPS — оба варианта дают его из коробки.

### Вариант A: GitHub Pages (рекомендуется — всё уже настроено в репозитории)

```bash
cd tg-expenses
git init
git add .
git commit -m "Mini App: учёт трат для двоих"
# создайте пустой репозиторий на github.com, затем:
git remote add origin https://github.com/USERNAME/tg-expenses.git
git branch -M main
git push -u origin main
```

1. В репозитории: **Settings → Pages → Build and deployment → Source:
   GitHub Actions**. Workflow `deploy-pages.yml` подхватится сам.
2. После push workflow задеплоит папку `frontend/`. URL будет вида
   `https://USERNAME.github.io/tg-expenses/`.
3. Keep-alive (чтобы Supabase не засыпал): **Settings → Secrets and variables
   → Actions → вкладка Variables → New variable**:
   - Name: `API_URL`
   - Value: `https://YOUR_PROJECT_REF.supabase.co/functions/v1/api`
   Workflow `keepalive.yml` сам пингует функцию каждые 3 дня.

Каждый следующий `git push` в `main` автоматически обновляет приложение.

### Вариант B: Vercel (проще кликами, без workflow)

1. [vercel.com](https://vercel.com) → Sign in через GitHub → **Add New → Project**
   → импортируйте репозиторий.
2. Настройки: **Framework Preset: Other**, **Root Directory: `frontend`**,
   Build Command — пусто, Output — пусто (статика как есть).
3. Deploy → URL вида `https://tg-expenses.vercel.app`.
4. Keep-alive через GitHub Actions из варианта A всё равно можно оставить
   (или пинговать любым бесплатным cron-сервисом).

Что проще: Vercel — если не хочется трогать настройки Pages (импорт → 2 поля →
Deploy). GitHub Pages — если репозиторий уже на GitHub и не нужен ещё один
сервис; деплой полностью описан файлом в репозитории.

### Проверка

Откройте URL в браузере — должна появиться надпись «Откройте приложение
через Telegram». Это нормально: вне Telegram нет initData, и приложение
(намеренно) не работает. Ошибок 404/500 быть не должно.

## Шаг 5 — привяжите URL к боту

1. **@BotFather** → `/setmenubutton` (или Bot Settings → Menu Button):
2. выберите вашего бота;
3. вставьте URL Mini App (из шага 4, обязательно `https://`);
4. задайте текст кнопки, например: `Траты`.
5. Откройте чат с ботом в Telegram на телефоне → кнопка «Траты» слева от поля
   ввода → приложение должно открыться и показать ваш месяц.

**Тест с двумя аккаунтами:** откройте кнопку с телефона девушки (её ID должен
быть в `allowed_users`). Добавьте трату с каждого аккаунта, закройте/откройте
приложение — оба должны видеть обе записи. Чужая запись не должна открываться
на редактирование. Попробуйте фильтр «Мои / Партнёра», смену месяца и бюджет.

## Известные ограничения

- **Supabase Free засыпает после ~7 дней неактивности.** Первый запрос после
  сна идёт медленно (или падает с ошибкой) — просто откройте приложение ещё
  раз, проект проснётся. Workflow `keepalive.yml` пингует проект каждые 3 дня,
  чтобы этого не происходило. Приостановленный вручную проект будится в
  Dashboard кнопкой Restore.
- **Лимиты Free tier** (на двоих с огромным запасом): БД 500 МБ,
  Edge Functions 500 000 вызовов/мес, 2 проекта на аккаунт. Каждая мутация
  делает 1 вызов функции — даже 100 трат в день это ~3000 вызовов/мес.
- **GitHub Pages**: только статика (нам и нужно), лимит 100 ГБ трафика/мес,
  репозиторий до 1 ГБ. Публичный репозиторий = код виден всем, но секретов
  в коде нет; данные защищены initData + allowed_users. Хотите приватный
  репозиторий с Pages — нужен платный план, тогда используйте Vercel
  (приватный репозиторий бесплатно).
- **initData живёт 24 часа** (проверка `auth_date` в функции). Если оставить
  приложение открытым дольше суток, запросы начнут отклоняться — закройте
  и откройте Mini App заново.
- **Один бот = один токен.** Если перевыпустите токен в BotFather — обновите
  секрет `TELEGRAM_BOT_TOKEN`, иначе валидация initData сломается.
- **Часовые пояса**: дата траты выбирается вручную (по умолчанию — сегодня
  по часам устройства), суммы хранятся без валюты (рубли). Мультивалютности нет.
- **Нет realtime**: изменения партнёра видны после переоткрытия приложения
  или смены месяца/любого действия. Для двоих этого достаточно.

## Что делать при ошибках

| Симптом | Причина и решение |
|---|---|
| «Невалидная подпись Telegram…» | Неверный `TELEGRAM_BOT_TOKEN` в secrets (опечатка, токен другого бота, перевыпущенный токен). Проверьте секрет. Также бывает при открытии не через Telegram или устаревшей initData (>24 ч) — переоткройте приложение. |
| «Доступ запрещён: ваш Telegram ID не в списке…» | ID не добавлен в `allowed_users`. SQL Editor: `insert into allowed_users values (ВАШ_ID, 'имя');` |
| Приложение открылось, но «Ошибка сервера (500)» | Смотрите логи: Dashboard → Edge Functions → api → Logs. Частое: миграция не выполнена (нет таблиц) или не задан секрет. |
| Первый запрос утром очень долгий / ошибка сети | Проект Supabase уснул. Откройте приложение повторно; проверьте, что keepalive-workflow включён и переменная `API_URL` задана. |
| CORS-ошибка в консоли браузера | Функция отвечает с `Access-Control-Allow-Origin: *` — если ошибка есть, значит запрос вообще не дошёл до функции (неверный URL в `config.js`, проект уснул/приостановлен). |
| Кнопка меню не открывает приложение | URL должен быть HTTPS и совпадать с задеплоенным. В BotFather проверьте Menu Button. На Desktop иногда нужен перезапуск клиента. |
| «Можно редактировать только свои записи» | Так и задумано. Если решите разрешить редактировать обоим — удалите проверку `row.user_id !== tgUser.id` в `update`/`delete` функции и задеплойте её заново. |
| Трата не появилась у партнёра | Нет realtime — переоткройте приложение или переключите месяц туда-обратно. |

## Как поменять список пользователей

```sql
-- добавить:
insert into public.allowed_users (telegram_id, note) values (333333333, 'кто-то');
-- убрать:
delete from public.allowed_users where telegram_id = 333333333;
```

Редеплой функции не нужен — список читается при каждом запросе.
